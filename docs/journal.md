# Journal

## 2026-11-19

- Cadrage : problème (les admins Plato organisent les tournois à la main, avec des sites externes et des captures d'écran), périmètre de la v0.1.0, choix de pile, relais, absents et liste d'attente (voir [décisions](decisions.md) D1 à D12).
- Maquettes : direction visuelle « pendule », thèmes sombre et clair.
- PR n°1 (fusionnée) : fondations du dépôt, reprises d'airpost (qualité, CI, hook, documents). Le contrôle gitleaks a d'abord échoué faute de la permission `pull-requests: read` ; corrigé sur ce seul job.
- PR n°6 (en cours) : authentification (voir [décision D13](decisions.md)). Sessions en base avec jeton haché, argon2id, CSRF en deux couches, limites de débit par IP et par compte, invitations et tickets de réinitialisation, script `create-owner`. 67 tests dont 33 d'intégration sur une vraie base PostgreSQL (`iamin_test`, refus de tourner sur une base dont le nom ne finit pas par `_test`), avec un service PostgreSQL ajouté à la CI. Leçons : (1) un verrouillage de compte gardé en mémoire survit d'un test à l'autre : le test dédié a son propre compte ; (2) `cookie` v2 n'est pas résolu avec le module CommonJS du projet : v1 ; (3) une fonction PowerShell qui renvoyait plusieurs valeurs a vidé un fichier de documentation : restauré depuis git, et `git diff --stat` systématique après toute réécriture de fichiers.
- PR n°5 (fusionnée) : `apps/api` (NestJS 11, Prisma 6, PostgreSQL 17 via Docker Compose). Configuration validée au démarrage avec zod (refus d'une origine CORS qui n'est pas exacte, cookie `Secure` obligatoire en production, valeurs jamais affichées dans les erreurs), `helmet`, CORS limité à l'origine de l'interface, sonde `/health` qui ne révèle rien en cas de panne, base exposée sur 127.0.0.1 uniquement. Vérifié pour de vrai avec une base : 200 quand elle répond, 503 quand on l'arrête. Ce test réel a trouvé un bug que les tests unitaires ne voyaient pas : `tsc` ne copiait pas le client Prisma généré dans `dist` (corrigé : le client se charge depuis `@prisma/client`). Le port 5432 était déjà pris sur la machine : `POSTGRES_PORT` rend le port configurable. Les scripts d'installation de pnpm 10 sont bloqués par défaut : seuls ceux de Prisma sont autorisés (`onlyBuiltDependencies`). L'audit de la CI a refusé deux failles « high » dans l'outil `prisma` (`deepmerge-ts` et `effect`, utilisés pour sa config, pas par l'API en marche) : forcées vers les versions corrigées avec `overrides` dans `pnpm-workspace.yaml`, à retirer quand Prisma les relèvera.
- PR n°4 (fusionnée) : générateurs de texte pour le chat dans `@iamin/engine` (inscrits et liste d'attente, VS d'un tour ou d'une journée, résultats, classement). Texte brut, un fait par ligne. Les pseudos viennent d'inscriptions publiques : nettoyés (retours à la ligne et caractères de contrôle supprimés) pour qu'un pseudo ne puisse pas ajouter de fausses lignes au message copié (risque R10).
- PR n°3 (fusionnée) : ligue dans `@iamin/engine`. Calendrier par la méthode des cercles (repos tournant si le nombre de joueurs est impair, aller-retour en option). Classement : points, confrontation directe, différence de score, score marqué, puis ordre du tirage. Leçon : réécrire un fichier avec `Get-Content` puis `Set-Content` sous PowerShell 5.1 a corrompu les accents (lecture en ANSI) ; lecture et écriture en UTF-8 explicite désormais, et `git diff --stat` avant de continuer.
- PR n°2 (fusionnée) : paquet `@iamin/engine`, arbre d'élimination directe. Tirage vérifiable : identifiants triés puis mélange de Fisher-Yates avec une graine, donc le résultat ne dépend pas de l'ordre d'inscription. Les byes vont aux têtes de série 1 à N (des joueurs tirés au sort), jamais deux dans le même match.
